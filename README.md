# Архивариус 📚

**Архивариус** — умный школьный бот для мессенджера MAX, который подключается к учебным чатам, индексирует сообщения с домашними заданиями и отвечает на вопросы учеников о ДЗ в формате естественного диалога.

---

## ⚠️ Важные особенности и ограничения (MVP)

Проект находится на стадии активного **MVP (минимально жизнеспособного продукта)**. Здесь нет полноценного многоуровневого кэширования, а в архитектуре присутствуют временные решения и ограничения:

1. **Даты строго в UTC:**  
   Все сообщения, дедлайны и временные метки хранятся в БД в **UTC**. Это связано со спецификой API мессенджера MAX (сообщения приходят без информации о локальных таймзонах пользователей). Единого решения по нормализации дат к локальному времени школ пока нет.
2. **Лимит на 3 чата:**  
   В текущей версии пользователю доступен выбор максимум из **3 чатов** для просмотра заданий.
3. **Сохранение доступа при выходе из чата:**  
   Если пользователь покидает группу, он всё равно сохраняет доступ к просмотру ДЗ этого чата в боте — механизм автоматической отвязки пользователей при выходе в MVP пока не реализован.
4. **Проксирование через ngrok:**  
   Входящие вебхуки бота проксируются через ngrok на выделенном домене (в конфигурации задействован токен разработчика).

5. **Мы уже работаем над исправлением других ошибок и у нас уже есть Roadmap**

## 🖥️ Системные требования

Для работы локального модуля искусственного интеллекта требуется видеокарта:
* **GPU:** Видеокарта NVIDIA с поддержкой CUDA (от **6–8 ГБ VRAM**).
* **LLM:** Локальная модель **`qwen2.5:7b-instruct-q4_K_M`** (вес квантизации ~4.7 ГБ, требует от ~4.5 ГБ видеопамяти).
* **Движок инференса:** Ollama (запускается автоматически внутри Docker-контейнера).

## 🚀 Быстрый запуск

Все сервисы проекта (Ollama, AI-агенты, Backend API, Бот, PostgreSQL 17 и Redis) разворачиваются одной командой:

```bash
docker compose up -d --build
```

> ⏳ **Обратите внимание:** при первом запуске контейнер `llm-model` автоматически скачивает модель `qwen2.5:7b-instruct-q4_K_M` (~4.7 ГБ). До завершения загрузки AI-сервис и бот будут ожидать готовности LLM.

## 🔍 Real-time мониторинг состояния (Healthcheck)

В репозитории есть интерактивный скрипт `check_status.sh`, который в **реальном времени** (с автообновлением каждые 2 секунды) отображает статус готовности всех контейнеров и сервисов:

```bash
./check_status.sh
# или
bash check_status.sh
```
*(Для однократной проверки без интерактивного дашборда используйте `./check_status.sh --once`)*

### Что отслеживает монитор в реальном времени:
* **Статус 6 контейнеров:** `database`, `redis`, `llm`, `llm-service`, `backend`, `bot`.
* **Готовность БД и кэша:** отклик PostgreSQL (`pg_isready`) и Redis (`PING → PONG`).
* **Статус LLM:** скачивание, наличие и прогрев модели `qwen2.5:7b-instruct-q4_K_M` в Ollama.
* **HTTP Healthcheck:** проверка доступности API бэкенда (`/api/health/`) и AI-сервиса (`/health/`).
* **Итоговый индикатор готовности:** когда все сервисы поднимутся, дашборд выведет сообщение о готовности к тестированию.
