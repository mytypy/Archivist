## О проекте

Проект — **Архивариус**, бот, который подключается к школьному чату, индексирует сообщния и по текстовому запросу пользователя (например, «что задали по алгебре на завтра?») возвращает структурированный ответ: список заданий, даты, авторов сообщений и упоминания контрольных работ.
Бот фильтрует информационный шум и работает в формате естественного диалога.
Продукт отличается от существующих ИИ-решебников тем, что не решает задачи за ученика, а решает организационную проблему — поиск информации в чате.

## Технологический стек

- **FastAPI** — веб-фреймворк.
- **PostgreSQL** — основная база данных.
- **Redis** — кэширование и другие задачи по мере необходимости.
- **SQLAlchemy** — работа с базой данных.
- **Pydantic** — валидация данных и схемы.

Подробные версии зависимостей указаны в `backend/requirements.txt`.

### Ключевые компоненты

- **`core/config.py`** — единственный источник конфигурации. Все настройки читаются из `.env` через `pydantic-settings` с соответствующими префиксами (`POSTGRES_`, `REDIS_`, `APP_`).
- **`db/manager.py`** — `DatabaseManager` управляет подключением к PostgreSQL (напрямую или через PG Bouncer). Модульный синглтон `cfg` создаётся на уровне модуля. Функция `get_db_session` — FastAPI Dependency для получения `AsyncSession`.
- **`db/utils.py`** — декоратор `db_errors_to_http` оборачивает CRUD-функции и транслирует ошибки БД в HTTP-ответы с нужными статус-кодами.
- **`models/`** — SQLAlchemy-модели наследуются от `Model` (`db/base.py`). Общие типы колонок (`int_pk`, `created_at_time`) определены в `db/base.py` как `Annotated`-алиасы.
- **`crud/`** — тонкие функции для отдельных операций с БД. Каждая функция декорирована `@db_errors_to_http` и принимает `AsyncSession`.
- **`api/routes/`** — FastAPI-роутеры. Бизнес-логика в обработчиках запросов использует CRUD-функции.
- **`api/dependencies/`** — FastAPI-зависимости (авторизация и т.д.).
- **`services/`** — внешние сервисы (Redis). Обёртка `Redis` инициализируется в lifespan приложения.

### Принятые подходы

- **Асинхронность** — asyncpg + async SQLAlchemy, async Redis.
- **Конфигурация** — `.env` + `pydantic-settings`, без хардкода.
- **Миграции** — Alembic с асинхронным `env.py`; URL берётся из `DatabaseManager`.
- **Обработка ошибок БД** — централизованная через декоратор `db_errors_to_http`, а не try/except в каждом обработчике.
- **Upsert** — `pg_insert(...).on_conflict_do_nothing(...)` для идемпотентного создания записей (user, chat).
- **Авторизация** — проверка секретного токена в заголовке через `hmac.compare_digest`.

### Правила добавления нового функционала

- Новая **модель** → `backend/models/<entity>.py`, наследование от `Model`, использование типов из `db/base.py`. Импортировать модель в `migrations/env.py` для видимости Alembic.
- Новые **CRUD-функции** → `backend/crud/<entity>.py`, обернуть `@db_errors_to_http`.
- Новый **роутер** → `backend/api/routes/<domain>/<domain>.py`, подключить к корневому `APIRouter` в `main.py`.
- Новая **Pydantic-схема** → `backend/schemas/request/` (входящие) или `backend/schemas/response/` (исходящие).
- Новая **зависимость** → `backend/api/dependencies/<domain>/`.
- Новый **внешний сервис** → `backend/services/<service_name>/`.

## Правила написания кода

- Придерживайся существующего стиля написания кода в проекте. Перед внесением изменений изучи похожие реализации.
- Пиши простой, читаемый и понятный код. Избегай чрезмерно сложных функций, абстракций и преждевременной оптимизации.
- Указывай типы всех параметров и возвращаемого значения функций. Пиши содержательные docstring-аннотации, объясняющие назначение функции, её параметры и результат там, где это уместно.
- Давай переменным, функциям, классам и модулям понятные имена.
- Следуй принципам **SOLID**, особенно принципу единственной ответственности (SRP). Не усложняй код ради формального соблюдения принципов.
- Не дублируй существующую логику. Перед добавлением новых классов, функций или зависимостей проверяй, нельзя ли переиспользовать уже имеющиеся.
- Не вноси изменения, не связанные с текущей задачей. Не добавляй функциональность, которую не просили реализовать.
